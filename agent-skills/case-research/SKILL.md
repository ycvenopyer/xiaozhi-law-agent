# 案例检索、裁判提炼与类案比较

## 适用条件与输入

用户需要找类似裁判、提炼裁判理由、比较支持或不利案例时使用。至少需要争点或一份可分析的裁判材料；优先读取用户已给的案由、事实、权利类型、法院层级、年份、程序和所代表的一方，不重复询问已知信息。

有争点但没有案例材料时，输出检索方案和材料缺口；没有争点但有文书时，可先提炼该文书并询问比较目标。要求“最新案例”或指定数据库，而当前没有相应访问能力时，说明范围后继续处理已有材料。

## 工作流程

1. 把本案整理成争点画像：关键行为、权利基础、请求及抗辩、决定性证据、程序阶段。将当事人主张与法院认定分开。
2. 在实际提供的知识库、文书和附件中筛选候选，按 [裁判阅读与身份核验](references/judgment-reading.md) 建立案例卡，保留原文定位及结论层级。
3. 按争点和决定性事实判断相关性，不以相同案由或同一个关键词代替可比性。识别能支持本方及可能不利的裁判，不能只选有利材料。
4. 比较多份裁判、出现结果相反或用户要求诉讼策略时，再读取 [类案比较方法](references/comparison-method.md)，分析事实、证据、规则版本及程序差异。
5. 使用 [类案比较底稿](assets/case-comparison.md) 输出；只有一份材料时缩减为单案卡，没有可核实案例时转为待检索清单。
6. 提炼可借鉴的论证步骤和对本案的限制，给出有依据的补充证据或检索方向，不从个案推算胜诉概率。

## 交付与完成条件

每份案例均有材料定位；案号、法院、日期、程序与效力只写可核实信息；事实、主张、裁判理由及结论已分离；与本案的相似点、重要差异和不利因素明确。结论说明参考价值及其边界。

## 不得越过的边界

没有相关材料时明确“当前资料中未找到可核实的案例”，不能编造案号、裁判日期、指导性案例身份或检索命中。只读节选不能称已审阅全文。个案裁判不当然具有普遍约束力。当前没有联网检索；不能声称访问过裁判文书网、案例库或阅读了用户仅提供网址的页面。敏感身份仅在本次分析必要范围内使用。
