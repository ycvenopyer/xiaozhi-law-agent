# 需求收集与风险检查

## 先提取现有信息

| 信息 | 影响 | 缺失时处理 |
| --- | --- | --- |
| 起草/审核/改某条款 | 决定交付形式 | 请求不清且会改变结果时先确认 |
| 合同类型与核心目标 | 决定条款结构 | 无法识别时补问，不能替用户决定交易类型 |
| 我方角色与立场 | 决定风险分配 | 可以先中立分析，但明确立场待确认 |
| 标的与权利范围 | 决定何物被开发、许可或转让 | 具体权利信息占位；不能凭空创造权属 |
| 法域与履行场景 | 影响效力、程序及救济 | 说明假设；需要具体效力结论时必须核验 |
| 价款、期限与交付 | 直接商业决定 | 用占位或备选，不能自行认定双方同意 |
| 正文、附件及修改稿 | 决定审阅范围 | 没有正文不能交付“已完成审核” |

缺失信息会使主体、权利范围或核心风险分配出现实质误判时，集中提出最关键的几个问题。用户明确要先出模板时不阻塞，使用可定位的占位符并列出待确认项。

## 审核方法

每条意见包含：原条款位置及要旨、风险发生的条件、对我方的具体影响、建议修改、必要的替换文本及与其他条款的关联。区分：文字歧义、商业不利、履行不可操作、权利边界不明、需要法律核验的问题。

风险优先级以影响和触发可能性说明理由，不给无依据的精确概率。原文已经处理某项风险时检查充分性，不机械列为“缺失”。仅收到节选时注明审阅范围，不能评价整份合同的完整性。

## 完成前检查

对齐主体简称、金额及币种、日期、定义、编号和附件；核对交付与验收、付款与权利变动、终止与保密/返还义务之间是否矛盾；区分“建议条款”与“双方已约定”。不要把模型建议写成签署事实。
