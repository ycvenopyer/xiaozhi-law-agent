

补充确认：FTO 初筛 MVP 采用“模式 A：CSV 回填”，不接入专利数据库 API，不自建数据库，不替用户执行检索。

【数据源与 Provider 设计】
- 默认实现 ManualCsvProvider：用户上传外部数据库导出的检索结果 CSV。
- 预留 PatentApiProvider 接口，但 P0 不实现、不调用、不假装能自动检索。
- 系统不要求用户提供数据库账号，不爬取任何商业数据库。

【用户工作流（必须按此实现）】
1. 门禁：显著提示仅接收已公开/已申请专利方案，未公开方案须脱敏；用户勾选确认后进入。
2. 输入：技术方案 + 目标市场（可多选）+ 可选排除项；做基础校验。
3. 特征提取：输出可编辑特征清单（编号、描述、类型、是否必要），用户确认后才能进入下一步。
4. 关键词扩展：按特征生成同义/上位/下位/英文表达；用户可锁定、排除、补充。
5. 检索式生成：输出分项检索式和聚合检索式，附字段限定、预期用途、目标数据库建议；每条可一键复制，附外部执行指引。
6. 用户外部执行检索并导出 CSV。
7. CSV 上传与字段映射：格式预检（编码、分隔符、表头、行数、是否含公开号）；自动猜测字段映射，用户可手动调整；映射不完整时提示缺字段及影响。
8. 解析、按公开号去重、初筛：输出命中特征、初筛理由、风险等级初稿（高/中/低/待核验）；法律状态缺失或无法判断统一标“未核验”，禁止推断。
9. 候选专利列表：可排序、筛选、标记纳入/排除、写复核备注。
10. 报告导出：Markdown/Word；包含方案摘要、特征、关键词、检索式、CSV 来源说明、字段映射记录、候选列表、初筛理由、复核备注；开头和结尾硬编码免责声明；残缺运行须显著标注缺失环节。

【CSV 处理要求】
- 支持 UTF-8/GBK 编码识别，支持逗号/制表符分隔。
- 内置常见数据库导出模板的字段映射预设（至少支持通用模板：公开号、标题、申请人、申请日、公开日、法律状态、摘要）。
- 映射模板可保存复用。
- 缺公开号时提示“无法去重和生成报告链接”，缺法律状态时全部标“未核验”。

【初筛要求】
- 每条候选专利必须给出“命中哪些特征、为什么给这个风险等级”的可读理由。
- 风险等级只是初稿，界面和报告都要标注“初筛等级，非侵权结论”。
- 不做 Claim Chart、不做等同侵权判断、不做法律意见书。

【验收标准（模式 A 版）】
1. 用 5 个已公开技术方案测试：特征清单可编辑、检索式可复制到至少一个外部数据库执行并返回结果。
2. 用至少 2 种不同格式的真实 CSV 测试：字段映射可自动猜测并手动调整，解析无崩溃，去重正确。
3. 候选专利列表每条都有命中特征和初筛理由；法律状态缺失时显示“未核验”。
4. 报告可导出，含免责声明和可追溯记录；残缺运行有显著标注。
5. 未勾选门禁确认时无法进入；缺目标市场时无法生成检索式；缺公开号时提示明确。
6. 不出现任何“自动检索”“已核验法律状态”“构成/不构成侵权”的表述。

【工作方式】
先输出：1）还需我确认的问题；2）模块与接口定义（含 ManualCsvProvider、CSV 映射、初筛、报告）；3）任务卡拆分（P0-1 门禁与输入、P0-2 特征/关键词/检索式、P0-3 CSV 解析与初筛、P0-4 报告与评测）；4）验收测试计划。不要直接编码。
