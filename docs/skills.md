# 小知 Skills

参考 [Codex 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)，使用独立目录、`SKILL.md` 与按需加载。这里实现的是小知后端的技能运行机制，不需要使用 OpenAI 专属模型，也没有嵌入 Codex CLI。

## 使用

在输入框点击 **Skills** 或发送 `/skills` 打开技能面板。选中后立即从后端加载该技能的完整主指令、基础参考和底稿模板，作为本次问题的系统提示词上下文；原有输入不会被模板覆盖，也不会自动发送消息或调用模型。输入框显示加载状态，可展开「查看已加载提示词」。加载失败可重试，未准备好时不能发送；取消后移除这部分上下文。

技能仅作用于本次请求，后续任务可重新选择，模型也可以依据描述主动加载需要的技能。可在消息开头直接输入：

| 命令 | 能力与数据来源 |
| --- | --- |
| `$statute-research` | 检索法条，核对已提供资料的版本和适用条件 |
| `$case-research` | 检索材料中的类似案例，比较事实和裁判理由 |
| `$ip-news` | 整理新闻、公告正文及其业务影响 |
| `$contract-drafting` | 起草或审核技术开发、许可、转让、保密、竞业限制合同 |

如 `$contract-drafting 请起草一份保密协议，我方为披露方……`。知产新闻不抓取网页，只有网址时需要补充正文。模型匹配与规范遵循取决于所选模型，显式选择更可控；没有启用工具调用能力的模型仍可使用显式选择注入的规范。

## 结构与运行

```text
agent-skills/<skill-id>/
  SKILL.md                  # YAML name/description + Markdown 工作规范
  agents/openai.yaml         # display_name / short_description / default_prompt
  resources.json             # 资源路径、用途及加载条件
  references/                # 来源检查、阅读方法、专项判断规范
  assets/                    # 法条底稿、类案表、资讯简报、合同工作稿等模板
scripts/build-skills.mjs     # 校验并生成前后端注册表
shared/skill-catalog.generated.ts                 # 前端元数据
backend/src/modules/agent/skill-instructions.generated.ts # 服务端元数据和完整规范
```

选择时请求 `/api/agent/skills/:id/prompt`，返回经过构建注册的规范及版本。真正生成时，前端只发送技能 ID、版本和任务数据，后端重新使用同一份规范组装系统 prompt；不信任客户端自带的系统提示词或任意文件路径。版本已变化时拒绝旧版本请求并提示重新加载。

按三层组织模型上下文：

1. 发现层：每轮只列各技能的名称与描述。
2. 激活层：显式选择或开头的 `$技能名`，在首个模型请求前加载 `SKILL.md`、`on-activation` 资源全文，以及资源目录；模型主动选择时用 `load_skill` 完成同样的加载。
3. 专项层：满足使用条件时，模型调用 `read_skill_resource(skill_id, path)` 读取 `on-demand` 参考或模板。例如新旧法比较读取时间适用检查，起草保密协议读取保密协议骨架，不把所有技能资源塞进每一轮。

SSE `skill` 事件显示实际使用的技能，资源读取显示为工具卡片；后端将 `skillIds`、`skillVersions` 及工具调用与回答一起保存到原有账号隔离的 PG 会话记录。重新生成保留原技能选择并使用当前版本，无需新增数据库迁移。基础规范不依赖额外工具调用即可注入；专项读取依赖所选模型的工具调用能力，不能仅凭文件存在就声称已经读取。

参考文件提供工作方法和核验规则，不是已更新的法律数据库；assets 是可改写的交付模板，不是事实、案例或法律依据。所有占位符须依据实际材料填写。

当前运行器支持指令、清单注册的 UTF-8 Markdown/文本/JSON/CSV 资源，不执行脚本，也不支持在线安装第三方技能。每个资源只能通过准确的注册路径读取；构建时校验目录边界、重复项、文件大小、SKILL.md 中的链接和用途，运行时不访问任意文件系统。不要把客户卷宗或未公开技术写进公共 Skill 文件。

## 每个技能应写清什么

- 名称与准确的触发描述，以及相似任务的分工。
- 适用条件、最少输入、何时可以开始、缺什么必须补问、何时允许占位。
- 真实可用的数据和工具，不能宣称具备的检索或验证能力。
- 可执行的分析流程，事实、来源、推断与缺口如何区分。
- 资源路由：哪份参考在什么情况下读，哪份模板服务哪种交付。
- 输出要求、定位与引用规则、完成前核验、无法完成时的降级方式。
- 实际权限和隐私边界；技能不能绕过认证和账号外发授权。

四个内置技能各有两份参考，共八份；交付模板共五份。合同技能另外提供按需读取的保密协议骨架。

## 新增或修改

1. 在 `agent-skills/` 新建与 `name` 一致的目录，使用小写英文、数字、连字符，最长 64 字符。
2. 编写 `SKILL.md`：frontmatter 只包含单行 `name`、`description`，正文按上面的内容组织；保持主文件简洁，将专项细节拆到参考文件。
3. 编写 `agents/openai.yaml`，参照现有文件。此版本只解析 `interface` 下三项双引号字符串，换行使用 `\n`；默认提示词开头带 `$技能名`。
4. 编写 `resources.json` 数组，每项包含 `path`、`description`、`load`。路径格式为 `references/<名称>.md` 或 `assets/<名称>.md`（也支持 txt/json/csv）；`load` 为 `on-activation` 或 `on-demand`。每项资源须在 `SKILL.md` 有相对链接并说明读取条件；单文件不超过 12,000 字符，基础指令和自动资源合计不超过 24,000 字符。
5. 执行 `npm run skills:build`、`npm run skills:check`、`npm run test:edgeone` 和 `npm run build`，检查界面并部署。前后端注册表及内容版本自动生成，不要手改生成文件。开发和构建也会重新生成。

EdgeOne 的云函数从 TypeScript 注册表打包，运行时无需读取本地 Markdown 或额外文件系统。当前按字母顺序显示技能；新增技能会自动出现在面板中。专用图标可在 `SkillIcon` 中补充。

## 搜索与隐私

网页搜索工具、适配器、配置读取与示例变量已删除，本地旧搜索变量也已移除。如果 EdgeOne 控制台仍配置了 `WEB_SEARCH_*` 或历史 Tavily Key，可删除这些失效变量；新版代码不会读取它们。需要重新部署后线上才会更新。

Skill 不是数据库、RAG 或新的信息来源。它组织模型处理现有资料的方法；未接入检索工具就不能核实实时新闻、现行法规或新案例。模型本身的联网产品能力也不等于当前 API 已获得该能力。

Skills 不扩大用户的数据访问范围。使用时仍受现有账号外发开关限制；配置了平台 Key 的现有模型可通过输入框底部的模型按钮选择。开启外发后输入、附件、启用的知识库及卷宗可能交给所选供应商，不能仅因使用 Skill 就认为材料不会外发。
